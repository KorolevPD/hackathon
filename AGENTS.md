# Правила для агентов

Этот файл задаёт единые правила для людей и ИИ-агентов, работающих с проектом.

## Формат Issue

Каждая Issue создаётся по шаблону `.github/ISSUE_TEMPLATE/business-task.md`.
Обязательные разделы:
- Пользовательская история
- Критерии приёмки в формате Given-When-Then
- Что входит в задачу
- Что не входит в задачу

Issue без критериев приёмки не считается готовой к работе.

## Чтение GitHub Issues

Агент читает Issues через `gh` CLI, не через MCP.

Правильный способ:
```bash
gh issue view <номер> --json title,body,comments --jq '.title + "\n" + .body'
```

## Границы агентов

### task-worker (Fullstack)
- Реализует **только** критерии приёмки из Issue.
- Не меняет файлы, не связанные с задачей.
- Не принимает решений о слиянии.
- Перед созданием PR проверяет, что критерии приёмки выполнены.

### reviewer (Тестировщик / Тимлид)
- Только чтение. Не меняет код.
- Используется для быстрого разбора большого PR.
- Возвращает список потенциальных проблем, решение принимает человек.

## Ветки и коммиты

- Ветка: `feat/issue-{номер}-краткое-описание`
- Коммит: `тип: краткое описание (#номер)`
- Типы: `feat`, `fix`, `docs`, `test`, `chore`
- Ветки задач создаются от `dev` и сливаются обратно в `dev` через PR.
- `dev` сливается в `main` только через PR, и только когда `dev` стабильна.
- Прямой push в `main` или `dev` запрещён.

## PR

- PR создаётся только после того, как Fullstack проверил критерии приёмки локально.
- PR должен ссылаться на Issue.
- PR не сливается без Approve от Тестировщика и проверки архитектуры Тимлидом.

## Запрещено

- Создавать `TASKS.md` или любой другой файл со списком задач в репозитории.
- Менять несвязанные файлы в рамках одной задачи.
- Сливать PR без ревью.
