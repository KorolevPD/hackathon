## Когда использовать

Fullstack вызывает этот skill, когда собирается начать новую задачу из Issue. На вход подаётся номер Issue (например, `/start-issue 42`).

## Шаги

1. **Извлеки номер Issue** из запроса пользователя. Если номер не указан или указан нечётко — задай уточняющий вопрос, не продолжай.
2. **Прочитай Issue** через `gh` CLI:
   ```bash
   gh issue view <номер> --json title,body,comments,state --jq '{title, body, state, comments: [.comments[].body]}'
   ```
   - Обязательно используй `--json`, иначе `gh` может открыть пейджер и заблокировать тебя.
   - Прочитай заголовок, тело, все комментарии и текущий статус.
3. **Проверь готовность задачи**:
   - Если Issue закрыт (`state` не `OPEN`) — сообщи и остановись.
   - Если в теле нет критериев приёмки или раздел «Критерии приёмки» пуст — сообщи и остановись: «Задача не готова к работе: нет критериев приёмки».
   - Если критерии есть, но непонятны — сформулируй 1–3 конкретных вопроса и предложи пользователю сначала уточнить их в комментарии к Issue, а не начинать код.
4. **Прочитай `AGENTS.md` и `DECISIONS.md`**, чтобы вспомнить правила веток, коммитов и границы агента.
5. **Проверь рабочее состояние git**:
   ```bash
   git status
   git branch --show-current
   git log --oneline -5
   ```
   - Если есть незакоммиченные изменения — сообщи и остановись, не создавай ветку.
   - Если текущая ветка не `dev` — предложи переключиться на `dev` (`git checkout dev`), затем обнови (`git pull`).
6. **Создай ветку** строго по правилу `AGENTS.md`:
   ```bash
   git checkout -b feat/issue-<номер>-<краткое-описание-латиницей>
   ```
   - Краткое описание возьми из заголовка Issue, переведи в латиницу и kebab-case.
   - Тип (`feat`/`fix`/`docs`/`test`/`chore`) определи по характеру Issue; если не уверен — спроси.
7. **Верни пользователю сводку**:
   - Номер и заголовок Issue
   - Созданная ветка
   - Критерии приёмки (кратко, списком)
   - Раздел «Затронутые области» из Issue (если есть)
   - Следующий шаг: «Можно начинать реализацию. Передай мне Issue и я приступлю к коду».

## Ограничения

- Не создавай Issue, не комментируй его и не меняй его статус.
- Не начинай писать код на этом шаге — это только подготовка.
- Если `gh` не установлен или не аутентифицирован — сообщи и остановись, не пытайся обойти через MCP.
- Не создавай ветку от `main`. Всегда от `dev`.
- Если ветка с таким именем уже существует — сообщи и предложи либо переключиться на неё, либо выбрать другое имя.
