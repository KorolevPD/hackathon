## Когда использовать

Аналитик вызывает этот skill, когда у него есть только представление о конечном результате фичи, но нет технических знаний и готового текста Issue.

## Вход

Аналитик предоставляет неформальное описание: какую проблему нужно решить, для кого, как должен выглядеть результат.

## Шаги

1. **Прочитай шаблон Issue**: открой `.github/ISSUE_TEMPLATE/business-task.md` и запомни его структуру и все разделы.
2. **Проанализируй проект**: определи, какие части кодовой базы или документации связаны с описанием аналитика. Заполни раздел «Затронутые области» на основе этого анализа. Если не уверен — отметь «Не знаю — нужно уточнить у Тимлида».
3. **Задай уточняющие вопросы** (если информации недостаточно): 3–5 вопросов, сфокусированных на критериях приёмки и границах задачи. **Не создавай Issue на этом шаге.**
4. **Сгенерируй черновик Issue** строго по структуре `business-task.md`:
   - Пользовательская история
   - Затронутые области
   - Критерии приёмки (Дано-Когда-Тогда, каждый пункт — проверяемый)
   - Что входит / что не входит
   - Способ проверки (шаги для Тестировщика)
   - Дополнительный контекст
